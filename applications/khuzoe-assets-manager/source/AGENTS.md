# Khuzoe Assets Manager

- App Windows separata da Khuzoe Updater, distribuita dal suo catalogo. Modificare l'Updater soltanto per integrazioni richieste. Non modificare moduli installati, database o impostazioni dei mondi Foundry.
- Pubblicare i sorgenti in applications/khuzoe-assets-manager/source nel repository pubblico Khuzoe/khuzoe-modules. application.zip, application.json e release.json restano nella cartella superiore per l'Updater. Non includere sorgenti C#, test, strumenti di sviluppo o dati utente nel pacchetto runtime. Allineare application.json, app/version.txt, app/app.manifest e la versione del lettore a ogni release runtime. Una pubblicazione dei soli sorgenti/documenti non deve rigenerare release immutabili già distribuite.
- C# 5 e .NET Framework 4.8, senza NuGet o runtime da installare manualmente.
- Sezioni: musiche e scene con editor di bozze locali. UI in italiano, percorso Foundry ricordato, strumenti preparati dall'app, nessun servizio residente.
- Scene: soltanto lettura di copie temporanee stabili dei database LevelDB. Non aprire mai i database originali con classic-level. Rispettare i livelli v14 e non introdurre scritture ai mondi. Il lettore Node ha dipendenze fissate in engine/package-lock.json; npm ci --ignore-scripts --omit=dev è necessario solo per gli sviluppatori.
- L'editor modifica un clone della proiezione letta, che non contiene il documento Foundry completo. Bozze e anteprime soltanto nello stato locale dell'app, immagini importate lette senza modificarle o copiarle nei dati Foundry. Non introdurre applicazione/sincronizzazione verso Foundry senza una richiesta esplicita.
- Interazione editor: niente serializzazione o scrittura per la sola selezione. Riutilizzare lo snapshot immutabile dell'ultima modifica e mantenere ordinata la coda delle scritture locali; completarla prima di terminare. Cache grafiche limitate e rilasciate al cambio immagini; verificare trasparenza, cambio texture, zoom e dimensioni quando si modifica il rendering.
- Immagini: tenere distinti originale, anteprima e ritaglio di dettaglio. Le coordinate della scena e le trasformazioni delle immagini non dipendono dalla risoluzione delle cache. Conservare immagini sovrapposte/affiancate come elementi separati e consentire coordinate esterne alla mappa. Per future selezioni/AI usare rettangoli nelle coordinate della scena e risultati come nuove immagini posizionate; non appiattire o sovrascrivere gli originali. Le generazioni AI non sono abilitate dalla 0.4.3.
- Gli MP3 vanno soltanto sotto `musics/` nella directory dati selezionata. Validare percorsi, collegamenti e nomi prima di scrivere. Non sovrascrivere file esistenti.
- Chiavi segrete e codici personali non devono entrare in sorgenti, log, ZIP o repository. Sessioni protette con DPAPI, autenticazione verificata dal backend.
- Le prove usano directory isolate sotto `build/` o directory temporanee. Non usare musiche o mondi veri come fixture.
- Compilazione: `tools/build-app.ps1`; test: `tools/build-app.ps1 -Test`; pacchetto: `tools/package.ps1`.
- Aumentare `app/version.txt` e allineare il manifest per ogni release distribuita.

- Muri AI (0.5.0): API soltanto tramite backend Khuzoe, con verifica DM/admin sul server. Niente chiavi nel desktop. Selezione, zoom e modifiche manuali non chiamano AI. Persistenza della ricevuta prima del POST; recupero solo tramite GET, senza duplicare richieste incerte. Conferma in anteprima separata e inserimento additivo nella bozza con un unico annulla. Non sostituire muri esistenti. I test usano sempre un fornitore simulato; non avviare analisi a pagamento automaticamente. Il modello è configurato nel Worker. Tenere server/wall-detection.js allineato alla copia nel sito.
